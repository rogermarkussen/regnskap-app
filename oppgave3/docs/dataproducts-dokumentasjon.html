DFO-data for 2026 - regnskap, budsjett og workflow

Denne filen beskriver de analyseklarerte Parquet-filene i data-ny/2026. Dette er 2026-uttrekket som bør brukes som standard i videre lokalt arbeid.

Kortversjon

116 770bokførte regnskapsrader for 2026
33 815workflowrader relevante for 2026
18 840periodiserte budsjettverdier for 2026

Bruk data-ny/2026 som primærkilde. Dette er enkle Parquet-filer, én fil per datasett, filtrert til det vi trenger for 2026-analyser.

Mappen data-ny på nivået over inneholder samme datasett som fullhistoriske enkle Parquet-filer. Den er nyttig når du trenger historikk, men dokumentasjonen her tar utgangspunkt i 2026-filene.

Hvordan lese filene lokalt

I motsetning til Spark-/Delta-lignende dataproducts-strukturen under data/dataproducts, er data-ny/2026 laget for enkel lokal analyse. Hvert datasett er én Parquet-fil. 

SELECT *
FROM read_parquet('data-ny/2026/agltransact.parquet');

For full historikk bruker du filene direkte i data-ny: 

SELECT *
FROM read_parquet('data-ny/awftaskfin.parquet');

De eldre filene direkte under data/, for eksempel data/agltransact.parquet, er gamle arbeidskopier og har andre radtall. Ikke bruk dem som kilde for nye 2026-analyser.

Workflowdata: hva er awftaskfin?

awftaskfin.parquet beskriver fakturaflyt/workflowoppgaver. Dette er ikke én rad per faktura og heller ikke én rad per bokført regnskapslinje. En faktura kan ha mange workflowrader: én for hvert steg, hver godkjenner, videresending, avvisning eller ventestatus.

2026-filen er filtrert slik at den inneholder hele flyter som er relevante for 2026. Derfor kan enkelte workflowrader ha dato fra før 2026 dersom de tilhører samme oid som en relevant 2026-flyt. Dette er med vilje: hvis vi bare beholdt rader med 2026-dato, kunne vi mistet starten på en fakturaflyt.

Viktige felt

FeltBetydning
oidWorkflow-/objekt-id. Brukes til å samle flere oppgaver i samme flyt.
task_id, orig_task_idOppgave og eventuell opprinnelig oppgave.
wf_statusStatus for oppgaven: aktiv, fullført, avvist, videresendt osv.
wf_user_idBrukeren oppgaven ligger hos eller er knyttet til.
real_userBrukeren som faktisk utførte handlingen, når handlingen er utført.
orig_userOpprinnelig bruker i workflowen.
action_dateNår handlingen ble utført.
distr_dateNår oppgaven ble distribuert/sendt i workflow.
ready_dateNår oppgaven ble klar.
col*_descr, col*_valueFakturainformasjon, ofte leverandørnavn, fakturanummer og bilagsnummer.

Hva kan vi finne ut?

  • Hvilke fakturaer som fortsatt har aktive workflowoppgaver.
  • Hvem en oppgave ligger hos nå, via wf_user_id og wf_status = 'ACT'.
  • Hvem som faktisk godkjente eller behandlet et steg, via real_user.
  • Hvor lang tid et steg tok fra distribusjon til handling.
  • Om en faktura er videresendt, avvist, automatisk behandlet eller fullført.
  • Alle steg i samme flyt, ved å gruppere på oid.

Finn aktive workflowoppgaver

SELECT
  oid,
  task_id,
  wf_status,
  wf_user_id,
  distr_date,
  ready_date,
  col1_descr, col1_value,
  col2_descr, col2_value,
  col3_descr, col3_value
FROM read_parquet('data-ny/2026/awftaskfin.parquet')
WHERE wf_status = 'ACT'
ORDER BY distr_date DESC
LIMIT 100;

Mål behandlingstid

WITH wf AS (
  SELECT
    oid,
    task_id,
    wf_status,
    wf_user_id,
    try_strptime(substr(distr_date, 1, 19), '%Y-%m-%dT%H:%M:%S') AS distr_ts,
    try_strptime(substr(action_date, 1, 19), '%Y-%m-%dT%H:%M:%S') AS action_ts,
    col2_value AS fakturanr,
    col3_value AS bilagsnr
  FROM read_parquet('data-ny/2026/awftaskfin.parquet')
)
SELECT
  oid,
  task_id,
  wf_status,
  wf_user_id,
  fakturanr,
  bilagsnr,
  date_diff('hour', distr_ts, action_ts) AS timer_til_handling
FROM wf
WHERE action_ts IS NOT NULL
  AND distr_ts IS NOT NULL
ORDER BY timer_til_handling DESC
LIMIT 50;

Se hele flyten for en faktura

I observerte rader er col2_value ofte fakturanummer og col3_value ofte bilagsnummer/flytbilag, men sjekk alltid col*_descr før du konkluderer. 

SELECT
  oid,
  task_id,
  orig_task_id,
  wf_status,
  action_code,
  wf_user_id,
  real_user,
  orig_user,
  action_date,
  distr_date,
  ready_date,
  col1_descr, col1_value,
  col2_descr, col2_value,
  col3_descr, col3_value
FROM read_parquet('data-ny/2026/awftaskfin.parquet')
WHERE col2_value = '5520011110026'
   OR col3_value = '900003892'
ORDER BY oid, try_cast(task_id AS integer), action_date;

Koble workflow mot regnskap

Start med fakturanummer når det finnes. I regnskapstabellen ligger dette ofte i ext_inv_ref. I workflow ligger det ofte i en av col*_value-kolonnene, typisk col2_value når col2_descr = 'Fakturanr'. 

WITH wf AS (
  SELECT
    oid,
    wf_status,
    wf_user_id,
    real_user,
    action_date,
    distr_date,
    col2_value AS fakturanr,
    col3_value AS workflow_bilagsnr
  FROM read_parquet('data-ny/2026/awftaskfin.parquet')
  WHERE col2_descr = 'Fakturanr'
),
regnskap AS (
  SELECT
    voucher_no,
    ext_inv_ref,
    account,
    dim_1,
    dim_2,
    dim_4,
    amount,
    description,
    period
  FROM read_parquet('data-ny/2026/agltransact.parquet')
)
SELECT
  r.voucher_no,
  r.ext_inv_ref,
  r.account,
  r.dim_1,
  r.dim_2,
  r.dim_4,
  r.amount,
  r.description,
  w.oid,
  w.wf_status,
  w.wf_user_id,
  w.real_user,
  w.action_date
FROM regnskap r
LEFT JOIN wf w
  ON r.ext_inv_ref = w.fakturanr
WHERE r.ext_inv_ref IS NOT NULL
LIMIT 100;

Ikke anta at workflow-bilagsnummer alltid er identisk med bokført voucher_no. I fakturaflyt kan det finnes egne kø-/flytbilag. Valider koblinger mot fakturanummer, leverandørtekst, beløp og dato før du trekker konklusjoner.

Budsjettdata for 2026

Budsjettverdiene ligger primært i apltransactvalue.parquet, der acc_period er avgrenset til 202601-202612. apltransact.parquet inneholder tilhørende budsjettlinjer, mens aplversion.parquet inneholder relevante versjoner. 

SELECT
  acc_period,
  sum(period_value) AS budsjett
FROM read_parquet('data-ny/2026/apltransactvalue.parquet')
GROUP BY acc_period
ORDER BY acc_period;

For analyse på konto og dimensjoner må budsjettverdier normalt kobles mot apltransact på egnet teknisk nøkkel, typisk agrtid eller trans_id, avhengig av hvilken detaljering du trenger.

Anbefalt startoppsett i DuckDB

CREATE OR REPLACE VIEW regnskap AS
SELECT * FROM read_parquet('data-ny/2026/agltransact.parquet');

CREATE OR REPLACE VIEW workflow AS
SELECT * FROM read_parquet('data-ny/2026/awftaskfin.parquet');

CREATE OR REPLACE VIEW budsjettverdi AS
SELECT * FROM read_parquet('data-ny/2026/apltransactvalue.parquet');

CREATE OR REPLACE VIEW budsjettlinje AS
SELECT * FROM read_parquet('data-ny/2026/apltransact.parquet');

SELECT period, account, dim_4, sum(try_cast(amount AS double)) AS regnskap
FROM regnskap
GROUP BY period, account, dim_4
ORDER BY period, account, dim_4;
